什么是restful架构   

1. 每个URI代表一种资源 
2. 客户端与服务端之间，传递这种资源的某中国表现层
3. 客户端通过GET、POST、PUT、DELETE、PATCH对服务器端资源进行操作，实现表现层的状态转化

在 Flask 中使用 **Flask-RESTful + CBV（基于类的视图）** 构建多应用（多模块）项目时，**核心模式就是你总结的这两步**：

---

### ✅ 标准套路（每个子应用/模块都这么写）：

```python
# 比如：user/views.py
from flask import Blueprint
from flask_restful import Api, Resource

# 1. 创建蓝图
user_bp = Blueprint('user', __name__, url_prefix='/api')  # 可选前缀

# 2. 创建 Api 实例并绑定到蓝图
user_api = Api(user_bp)

# 3. 定义 CBV 资源类
class UserList(Resource):
    def get(self): ...
    def post(self): ...

class UserDetail(Resource):
    def get(self, user_id): ...

# 4. 注册资源路由（关键！）
user_api.add_resource(UserList, '/users')
user_api.add_resource(UserDetail, '/users/<int:user_id>')
```

然后在主应用中注册蓝图：
```python
# app/__init__.py
from .api.user.views import user_bp
app.register_blueprint(user_bp)
```

---

## 🆚 对比传统 FBV（函数视图）

| 内容 | 传统 FBV（函数） | RESTful CBV（类） |
|------|----------------|------------------|
| 路由注册 | `@bp.route('/users', methods=['GET', 'POST'])` | `api.add_resource(UserList, '/users')` |
| 方法分离 | 一个函数处理所有方法（或拆多个函数） | 一个类，`get`/`post`/`put` 各司其职 |
| 参数解析 | 手动 `request.get_json()` | 可用 `reqparse`（或 Marshmallow） |
| 代码组织 | 多个函数分散 | 逻辑聚合在一个类中 |

> 💡 **CBV 的优势**：  
> - 更符合 RESTful 语义（一个资源对应一个类）  
> - 避免大量 `if request.method == 'POST'` 判断  
> - 易于复用（如继承基类加认证）

## 🧩 多 App 项目中的典型结构（再次确认）

```
app/
├── api/
│   ├── __init__.py
│   ├── user/
│   │   ├── __init__.py
│   │   └── views.py      ← 这里写 user_api = Api(bp) + add_resource
│   ├── product/
│   │   └── views.py      ← 同样模式：product_api = Api(bp) + add_resource
│   └── order/
│       └── views.py
```

每个 `views.py` 都重复这个模式，**高度一致、易于维护**。

## ⚠️ 注意事项（避免踩坑）

1. **不要混用全局 `Api(app)` 和局部 `Api(blueprint)`**  
   → 推荐每个模块用自己的 `Api(bp)`，解耦清晰。

2. **路由前缀只写一次**  
   - 要么在 `Blueprint(url_prefix='/api')` 里写  
   - 要么在 `add_resource(..., '/api/users')` 里写  
   → **不要两边都写！**

3. **文件命名规范**  
   - 视图文件建议叫 `resources.py` 或 `api_views.py`（更语义化）  
     （因为 RESTful 中叫 “Resource” 而不是 “View”）

   ```python
   # 推荐
   from .user.resources import user_bp
   ```

4. **大型项目可进一步封装基类**
   ```python
   class BaseResource(Resource):
       method_decorators = [auth_required]

   class UserList(BaseResource):
       def get(self): ...
   ```

## 返回json格式  

我们尝试返回mysql中的数据,但是照着以前的方式是不行的   

所以我们需要引入装饰器,并定制返回的内容  
```python
from flask_restful import fields, marshal_with,Resource
resource_fields={
    'id':fields.Integer,
    'username':fields.String,
    'phone':fields.String,
    'regi_date':fields.DateTime
}

# step2:创建CBV
class Userlst(Resource):
    #tips:引用装饰器来定制返回的信息，就是上面我们定义的那个
    @marshal_with(resource_fields)
    def get(self):
        users = User.query.all()
        # return users[0] #测试第一个
        return users
```

marshal_with还有一个类似与fastapi中指定返回的数据限制

```python
resource_fields = {
    'id': fields.Integer,
}


# step2:创建CBV
class Userlst(Resource):
    # tips:引用装饰器来定制返回的信息，就是上面我们定义的那个
    @marshal_with(resource_fields)
    def get(self):
        return {
            'id': fields.Integer,
            'username': fields.String,

        }
```

这样即使要返回两个但是因为使用了定制返回，也就是只返回id,不会报错
